多重分支：if...else if...else 結構介紹

當條件超過兩個以上時，單純的 if...else 無法滿足需求，必須使用 if...else if...else 來依序比對多種可能性。

1. 語法結構格式

if (條件A) {
    // 當「條件A」成立時執行
} 
else if (條件B) {
    // 當「條件A」不成立，且「條件B」成立時執行
} 
else {
    // 以上所有條件都不成立時執行（可選）
}

3. 範例：家用電費分段級距計算

#include <iostream>
using namespace std;
int main() {
    int kwh;
    double bill = 0.0;
    cout << "請輸入本月用電度數：";
    cin >> kwh;
    
    if (kwh <= 120) {
        bill = kwh * 1.63;
    }
    else if (kwh <= 330) {
        bill = 120 * 1.63 + (kwh - 120) * 2.10;
    }
    else if (kwh <= 500) {
        bill = 120 * 1.63 + 210 * 2.10 + (kwh - 330) * 2.89;
    }
    else {
        bill = 120 * 1.63 + 210 * 2.10 + 170 * 2.89 + (kwh - 500) * 3.94;
    }
    
    cout << "本月預估電費總計：" << bill << " 元" << endl;
    return 0;
}

巢狀 if 敘述 (Nested if)

當一個條件成立之後，還要進行第二層甚至更多層的細部條件判斷時，就會用到巢狀 if。

1. 格式說明

if (條件A) {
    // 當 條件A 為真時執行
    if (條件B) {
        // 當 條件A 與 條件B 皆為真時執行
    } else {
        // 當 條件A 為真，但 條件B 為假時執行
    }
} else {
    // 當 條件A 為假時執行
}

3. 範例：遊樂園門票與快速通關購買判定

#include <iostream>
using namespace std;
int main() {
    int height;
    char hasFastPass;
    cout << "請輸入您的身高 (公分)：";
    cin >> height;
    
    // 第一層：檢查身高是否達到遊樂設施基本安全門檻 (130公分以上)
    if (height >= 130) {
        cout << "身高合格！請問是否有購買快速通關？(y/n)：";
        cin >> hasFastPass;
        
        // 第二層巢狀：根據是否有快速通關安排專屬通道
        if (hasFastPass == 'y' || hasFastPass == 'Y') {
            cout << "請走【VIP 快速通關通道】，優先搭乘！" << endl;
        } else {
            cout << "請走【一般排隊通道】，預計等待 40 分鐘。" << endl;
        }
    } else {
        cout << "未滿 130 公分，基於安全考量無法搭乘此項設施。" << endl;
    }
    return 0;
}

⚠️ 學生最易犯錯的 5 大觀念與寫程式陷阱

陷阱一：多重分支條件順序顛倒（邏輯覆蓋錯誤）

在 if...else if...else 中，條件是由上往下依序比對。如果把範圍大的條件寫在最上面，那麼數值會在通過第一關時就被攔截，導致永遠無法執行到後續更精細的條件判斷。

陷阱二：巢狀結構中大括號配對錯誤導致「懸置 else (Dangling else)」

當有多層 if...else 卻省略大括號時，else 會自動與最近且尚未配對的 if 結合。這常導致邏輯解讀與程式實際執行路徑不一致，建議每一層都要加上 {}。

陷阱三：漏掉預設的最後防線 (缺少 else 分支)

在編寫多重分支時，如果情境並非全面涵蓋，卻漏寫了最後的 else，當所有指定條件皆不成立時，程式會默默略過所有區塊，導致潛在的未預期輸出或變數無初值狀態。

陷阱四：條件區間交疊或不連續（漏失數值區間）

例如想表達不同區段的數值，卻在撰寫時留下了斷層，導致部分邊界數值變成「灰色地帶」無法被正確歸類。

陷阱五：在巢狀條件內重複宣告同名變數

在不同的內層區塊中不小心重複宣告相同名稱的區域變數，導致變數有效範圍混淆，造成編譯器報錯。
